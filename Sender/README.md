# Sender — 发送端固件（称重板）

GD32E230F6 称重板固件：读 4 路 HX711 称重传感器 + 电池电压，经 E22-400T22S
LoRa 模组发出。**整个系统的数据源头，WB 协议在这里定义。**

---

## 1. 硬件

### 主控：GD32E230F6（TSSOP-20）

| 引脚 | 功能 | 说明 |
|---|---|---|
| PA0 / PA1 | DOUT / SCK — HX711 #1 | 传感器 1 |
| PA2 / PA3 | DOUT / SCK — HX711 #2 | 传感器 2 |
| PA4 / PA5 | DOUT / SCK — HX711 #3 | 传感器 3 |
| PA6 / PA7 | DOUT / SCK — HX711 #4 | 传感器 4 |
| PA9 / PA10 | USART0 TX / RX | → E22 模组 |
| PB1 | ADC_CHANNEL_9 | 电池电压采样 |
| PA13 / PA14 | SWDIO / SWCLK | 烧写调试 |

> 引脚与「Weightboard 板」原理图逐一核对过。该封装**没有 PA11/PA12**。

### 外围器件

| 器件 | 说明 |
|---|---|
| HX711 ×4 | 24 位称重 ADC，SOP-16 |
| E22-400T22S | LoRa 收发模组，9600 8N1 透传 |
| TP4056 | 锂电池充电管理 |
| Q1 (PMOS) + SW1 | 电源防反接 / 总开关 |
| SW6 拨码开关 | **手动设置 E22 的 M0 / M1**（当前 MCU 控制不到） |
| J1 | 18650 电池座（单节） |
| J2~J5 | 4 路称重传感器接口 |

### 原理图里的关键网络

```
'M0'   ; R17.2 SW6.2 U6.20      ← M0 只接拨码开关（MCU 未连接）
'M1'   ; R16.2 SW6.4 U6.21      ← M1 只接拨码开关（MCU 未连接）
'VBAT_ADC' ; R3.2 R4.2 U1.14    ← 分压 1MΩ + 470kΩ
'TX_LoRa' / 'RX_LoRa'           ← U1.17 / U1.18
```

## 2. 编译

```
用 Keil uVision5 打开  weight.uvprojx
目标芯片：GD32E230F6
编译器：  ArmClang 6（AC6）
```

**编译注意事项**

| 项 | 说明 |
|---|---|
| 编译器必须选 AC6 | AC5 会报许可证错误 `C9555E` |
| 优化等级 | 用 **-O3**；DEBUG 档（-O0）会因代码膨胀超 Flash（`L6407E 0x1620 bytes`） |
| Flash / RAM | 128 KB / 20 KB。上一次构建：Code 43104 / RO 4500 / RW 504 / ZI 11176 |
| ⚠️ RAM 预算 | **ZI 不能随意增大**。曾因环形缓冲从 512 B 加到 4 KB 导致 RAM 到 14.9 KB → 栈溢出黑屏。加缓冲/数组前先算总量 |
| 输出 | `MDK-ARM\project\project.hex`（或 `Objects\weight.hex`） |

命令行构建：

先将 Keil 的 `UV4.exe` 所在目录加入 PATH；以下命令在 `Sender/` 中执行。

```powershell
UV4.exe -b weight.uvprojx -j0 -o build.log
# 退出码：0=干净  1=有告警  >=2=有错误
```

## 3. 数据协议（WB 协议）

板子每轮采集完成后发出**一行 ASCII 文本**，以 `\r\n` 结尾。

### 3.1 新版（带板号，11 字段）— 当前固件

```
WB,板号,序号,板子毫秒,OK掩码,重量0,重量1,重量2,重量3,电池mV,电量%\r\n
```

### 3.2 旧版（无板号，10 字段）— 兼容保留

```
WB,序号,板子毫秒,OK掩码,重量0,重量1,重量2,重量3,电池mV,电量%\r\n
```

上位机自动识别两种格式（判据：字段 3 是否为两位十六进制掩码），
所以**可以分批升级板子**而不会出现数据断档。

### 3.3 字段定义

| 字段 | 名称 | 类型 | 说明 |
|---|---|---|---|
| 0 | 帧头 | 文本 | 固定 `WB` |
| 1 | **板号** | 整数 | `BOARD_ID`，1~42 |
| 2 | 序号 | 整数 | `seq`，每发一帧 +1 |
| 3 | 板子毫秒 | 整数 | `millis()`，上电起累计毫秒 |
| 4 | OK 掩码 | 2 位十六进制 | `ok_mask`，bit0~bit3 对应 4 路；`0F` = 4 路全成功 |
| 5~8 | 重量 0~3 | 有符号整数 | `weight_g[0..3]`，**单位标称为克**（见下方警告） |
| 9 | 电池电压 | 整数 | `bat_mv`，单位毫伏 |
| 10 | 电量 | 整数 | `battery_percent(bat_mv)`，0~100 |

### 3.4 实测样例

```
WB,2375,2574362,0F,-11063,-8748,-3085,-13788,3818,57
```

### 3.5 ⚠️ 重量字段当前不是克

```c
static int32_t hx_zero[SENSOR_COUNT]           = {0, 0, 0, 0};
static int32_t hx_counts_per_gram[SENSOR_COUNT] = {1, 1, 1, 1};
```

标定数组未填写，所以 `hx711_to_gram()` 实际返回的是 **HX711 原始计数**：

```c
return (raw - hx_zero[ch]) / scale;   // scale=1、zero=0 → 等于 raw
```

**待做**：放已知砝码标定，填入 `hx_zero`（空载读数）与 `hx_counts_per_gram`（计数/克）。

### 3.6 上电提示行

板子上电后先发两行纯文本，上位机会单独识别、不计入解析失败：

```
BOOT_SYSTICK
ADC_INIT_OK
```

## 4. 关键参数与函数

### 宏定义（文件顶部）

| 宏 | 当前值 | 说明 |
|---|---|---|
| `SENSOR_COUNT` | `4U` | 称重传感器路数 |
| `SAMPLE_COUNT` | `5U` | 每路每轮采样次数 |
| `SAMPLE_INTERVAL_MS` | `200U` | 采样间隔，5×200ms = 1 秒 |
| `SAMPLE_JITTER_MS` | `6U` | 采样间隔随机抖动上限，防多板持续撞包 |
| `USE_HX711_CH_MASK` | `0x0FU` | 启用哪几路（bit0~3） |
| **`BOARD_ID`** | **`1U`** | **板号，每块板子必须改成不同值（1~42）** |
| `ADC_REF_MV` | `3300U` | ADC 参考电压 |
| `ADC_MAX` | `4095U` | 12 位 ADC 满量程 |
| `VBAT_R_HIGH_KOHM` | `1000U` | 电池分压上臂 |
| `VBAT_R_LOW_KOHM` | `470U` | 电池分压下臂 |
| `BAT_EMPTY_MV` | `3300U` | 电量 0% 对应电压 |
| `BAT_FULL_MV` | `4200U` | 电量 100% 对应电压 |

### 时序

- 时基：IRC8M（8 MHz）+ `SysTick_Config(8000U)` → 1 ms
- 串口：USART0 @ **9600 8N1**，PA9/PA10
- 每轮耗时：5 次采样 × 200 ms ≈ **1 秒**（另加抖动 0~5 ms），即约 **1 帧/秒**
- 错峰启动：`delay_ms((BOARD_ID - 1U) * 100U)`，42 块板摊在 4.1 秒内

### 主要函数

| 函数 | 作用 |
|---|---|
| `hx711_read(ch, &raw)` | 读一路 HX711 原始值（24 位，含符号扩展） |
| `hx711_to_gram(ch, raw)` | 原始值 → 克（依赖标定数组） |
| `battery_mv_read()` | 读 8 次 ADC 取平均，再按分压比算回电池电压 |
| `battery_percent(mv)` | 线性映射 3300~4200 mV → 0~100% |
| `send_packet(...)` | 组帧并用 `lora_send_*` 逐字段发出 |
| `rand_next()` | xorshift32 伪随机，用于采样抖动 |
| `battery_adc_init()` | ADC 初始化（**注意 `adc_calibration_enable()` 被注释掉了**） |

## 5. 功耗现状与低功耗改造

### 当前功耗（连续工作）

| 器件 | 状态 | 电流 |
|---|---|---|
| E22-400T22S | **透传待机（射频接收常开）** | **16 mA** ← 最大项 |
| HX711 ×4 | 一直上电转换 | **6 mA** |
| GD32E230 | 8 MHz 常跑 + SysTick 轮询 | ~3.5 mA |
| 电池分压 R3/R4 | 常接 | 2.2 µA |
| **合计** | | **≈ 25.5 mA** |

**单节 18650（2500 mAh，可用 70%）→ 约 2.6 天**，且与发送频率无关（全是固定消耗）。

### 改造方向（详见 [硬件改造方案](../UI/docs/硬件改造方案.md)）

| 优先级 | 改造 | 收益 |
|---|---|---|
| **P0** | E22 的 M0/M1 改由 MCU 控制 | **16 mA → 6 µA** |
| **P0** | 加 32.768 kHz 晶振，MCU 进 Deep-sleep | 3.5 mA → µA 级 |
| **P1** | 4 颗 HX711 加 P-MOSFET 负载开关 | 6 mA → 间歇 |
| **P1** | 帧格式改二进制 24 字节 + UART 提至 115200 | E22 活跃窗口缩 6 倍 |
| **P2** | 缩短 HX711 稳定时间 / 换 HX717 | 1 秒/次下省最多 |
| ❌ 不必做 | MCU 降频 72→8 MHz | 净收益 ≈ 0（省电流但任务变慢） |

预期：**5 秒/次 + 双节并联 → 约 6 个月**；1 秒/次 + 双节 → 约 3 个月。

## 6. 板号分配流程

```c
/* main.c 顶部 */
#define BOARD_ID            1U      // ← 每块板子改成不同的值
```

1. 改成 `1U` → 编译 → 烧写 → 记录板子物理位置
2. 改成 `2U` → 编译 → 烧写 → …依次到 `42U`
3. 上位机「板号总览」会自动按板号显示每块板子的四路数值

> 42 次改源码+编译比较费事。若日后想省事，可改为运行时确定板号
> （读某个 IO 电平 / 按键次数 / 存进 Flash），但当前设计是编译期写死。
